# 수동 테스트 시나리오 + 적합성 선언 템플릿

자동 도구가 못 잡는 **60~70%**를 잡는 핵심 단계. 국내 WA 인증의 **3차 사용자 심사**가
실제 장애인 사용자 평가이므로, 출시 전 아래를 직접 수행해 통과 가능성을 끌어올린다.

---

## 1. 키보드 전용 테스트 (마우스 금지)

마우스를 치우고 **Tab / Shift+Tab / Enter / Space / ↑↓←→ / Esc** 만으로 전 기능 수행.

| 확인 | 합격 기준 |
|------|-----------|
| Tab 순서 | 시각적 순서와 일치, 논리적 흐름 |
| focus 표시 | 모든 단계에서 **현재 초점이 눈에 보임**(outline) |
| 키보드 함정 | 어떤 요소에도 갇히지 않음(Tab으로 빠져나옴) |
| 모달 | 열면 모달로 초점 이동, Tab이 모달 내 순환, Esc로 닫힘, 닫으면 트리거로 복귀 |
| 드롭다운/메뉴 | Enter/Space로 열기, ↑↓ 이동, Esc 닫기 |
| 커스텀 위젯 | 탭/아코디언/콤보박스 APG 키 동작 |
| 스킵 링크 | 첫 Tab에서 "본문 바로가기" 노출·동작 |
| 폼 제출 | 오류 시 첫 오류 필드로 초점 이동 |

> cmux로 초점 추적: `SKILL.md` §3-3의 `document.activeElement` 폴링 활용.

## 2. 스크린리더 청취 테스트

권장 조합: **Windows + NVDA**(무료), **macOS/iOS + VoiceOver**, **Android + TalkBack**,
국내 인증 대비 **센스리더**. (`standards.md` §4)

### NVDA 핵심 단축키
| 키 | 동작 |
|----|------|
| NVDA(Insert) + ↓ | 전체 읽기 |
| H / Shift+H | 다음/이전 제목(heading) |
| K | 다음 링크 / F: 폼 필드 / B: 버튼 / T: 표 / D: 랜드마크 |
| Insert + F7 | 요소 목록(제목·링크·랜드마크 한눈에) |
| Tab | 초점 이동(폼 모드) |

### 청취 체크리스트
- [ ] **이미지**: 정보성 이미지가 의미 있게 읽힘, 장식 이미지는 안 읽힘
- [ ] **제목 구조**: H로 훑었을 때 페이지 목차가 논리적(h1→h2→h3, 도약 없음)
- [ ] **링크/버튼**: 이름만 듣고 목적 파악("여기", "버튼" 등 모호 ✕)
- [ ] **폼**: 라벨·필수·설명·오류가 모두 읽힘, 입력 모드 전환 자연스러움
- [ ] **상태 변화**: 로딩·토스트·검색결과수·정렬이 라이브 영역으로 들림
- [ ] **모달**: 열림 안내 + 내부에 갇혀 배경이 안 읽힘
- [ ] **SPA 라우팅**: 페이지 이동이 제목/안내로 들림(→ `router-focus.md`)
- [ ] **표**: 헤더-셀 연관이 읽힘("이름 열, 홍길동")
- [ ] **언어**: 한국어로 정확히 발음(lang 설정), 외국어 구절 전환

## 3. 저시력 / 인지 테스트
- [ ] 브라우저 **200% 확대** + OS **400% 확대**에서 콘텐츠/기능 유지
- [ ] 폭 **320px**에서 가로 스크롤 없이 1열 리플로우(`mobile-responsive.md`)
- [ ] **색만으로** 정보 전달하는 곳 없음(에러·필수·상태)
- [ ] 명도 대비 4.5:1(도구 + 눈)
- [ ] **고대비/강제색 모드**에서 윤곽·아이콘 유지
- [ ] 모션 축소 설정에서 자동재생/큰 애니메이션 멈춤
- [ ] 자동 갱신/시간제한에 정지·연장 수단

## 5. 적합성 선언 / VPAT (대외 제출·해외용)

해외(미국 등)는 인증마크 대신 **적합성 선언서**(Conformance Claim) 또는 **VPAT**
(Voluntary Product Accessibility Template)로 접근성 수준을 문서화한다.

### 적합성 선언 최소 항목 (WCAG-EM 기반)
```markdown
# 접근성 적합성 선언

- 대상: https://example.com (2026-06-17 평가)
- 목표 수준: WCAG 2.2 Level AA / KWCAG 2.2
- 평가 범위: 홈, 로그인, 마이페이지, 결제 (대표 페이지 + 핵심 플로우)
- 평가 방법: 자동(axe-core, Lighthouse) + 수동(키보드, NVDA/VoiceOver) + cmux 동적 점검
- 평가 도구/환경: NVDA 2025 + Chrome, VoiceOver + Safari, 센스리더
- 결과 요약: AA 충족 / 부분 충족 항목과 개선 일정 명시
- 예외/한계: (예) 제3자 결제 위젯은 공급사 의존
- 담당/연락처: a11y@example.com
```

> VPAT는 각 WCAG 성공기준을 Supports / Partially Supports / Does Not Support / N/A로
> 표기하고 근거를 적는다. 미국 조달·B2B 계약에서 요구되는 경우가 많다.
